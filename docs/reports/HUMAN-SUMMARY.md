# สรุปผลงาน NavSentry v0.1.0 (ฉบับอ่านง่ายสำหรับคน)

วันที่ 31 ต.ค. 2026 · Repository: `cognivex006/navsentry` (**Public**)

## สรุปใน 30 วินาที

- ✅ **ได้เครื่องมือที่ใช้งานได้จริงแล้ว** NavSentry v0.1 ตรวจความปลอดภัยเว็บแบบ "สังเกตอย่างเดียว" (ไม่ยิง payload ไม่แก้ข้อมูล) ได้อัตโนมัติ **20 เรื่อง** และออกรายงานได้ 3 รูปแบบ (Markdown ไทย/อังกฤษ, JSON, SARIF)
- ✅ **มีคลังเคส 50 เคส** ที่สกัดจากเอกสาร PDF/DOCX ทั้ง 6 ไฟล์ แบ่ง 13 หมวด ทุกเคสมี ID ถาวร (เช่น `NSC-CONF-001`) ผูกกับ **OWASP Top 10 ทั้งปี 2021 และ 2025**, CWE, WSTG และ ASVS 5.0 และมี Prompt ให้สั่ง Agent ได้ทันที 3 แบบ คือ ตรวจสอบ / แก้ไข / ตรวจซ้ำ
- ✅ **มีระบบกันแก้แล้วพัง** คำสั่ง `compare` เทียบก่อน/หลังแก้ได้ว่า Response ที่ผู้ใช้จริงได้รับ (status, ชนิดข้อมูล, โครงสร้าง JSON) **ไม่เปลี่ยน**
- ✅ **ไม่ใช้ GitHub Actions เลย** ใช้ด่านตรวจในเครื่อง `npm run gate` (8 ด่าน) แทน และศึกษาเงื่อนไขการใช้บริการ (ToS/AUP) ของบริการภายนอกทุกตัวแล้ว
- ⚠️ **ยังไม่ครบตาม Master Prompt** อีก 5 เรื่องใหญ่ คือ ตรวจผ่าน Browser, ทดสอบสิทธิ์ข้ามผู้ใช้ (IDOR), เรียกผ่าน curl/PowerShell, ทดสอบ SCA fixture และการใช้ Skill จากโปรเจกต์อื่น (แผนอยู่ใน [DEV-PLAN](../DEV-PLAN.md))

## ปัญหาที่พบใน Master Prompt และการตัดสินใจ

| ระดับ | ปัญหา | ตัดสินใจอย่างไร |
|---|---|---|
| 🔴 ต้องแก้ทันที | Prompt สั่งให้ใช้ CI / workflow actions / dependency-update PR อัตโนมัติ | ตัดทิ้งทั้งหมด ใช้ด่านตรวจในเครื่องแทน (ADR-0002) |
| 🔴 ต้องแก้ทันที | Repo เป็น **Public** แต่เอกสารต้นทางมีชื่อลูกค้า, host, IP, path ของ source | ทำข้อมูลให้เป็นนิรนามเป็น SRC-A…F และมีด่านตรวจ GATE-08 + test กันหลุด |
| 🔴 ต้องแก้ทันที | ไม่ได้ระบุให้ศึกษา ToS ของ SaaS (OSV, NVD, Postman, AI provider, ZAP, browser binary) | v0.1 **ไม่ใช้ SaaS เลย** ทุกตัวถูกบันทึกสถานะไว้ใน `governance/third-party.json` |
| 🔴 ต้องแก้ทันที | ไม่มีกลไกกันไม่ให้การแก้ช่องโหว่ไปเปลี่ยนผลลัพธ์ของผู้ใช้จริง | เพิ่ม response contract + `compare` + "ข้อควรระวัง" ในทุกเคส |
| 🟠 ระวัง | ช่องโหว่บางชนิดในเอกสาร (SQLi, Script Injection, Smuggling, DoS) ต้องยิง payload จริง | ไม่ทำอัตโนมัติ ทำเครื่องหมาย manual-active และมี Prompt สำหรับทดสอบโดยได้รับอนุญาตเท่านั้น |
| 🟠 ระวัง | Scanner รายงานผิดได้ (เลข 13 หลักที่ไม่ใช่บัตรประชาชน, HPKP ที่เลิกใช้แล้ว) | ใช้ checksum ตรวจเลขบัตร, ผลแบบ pattern ตั้งเป็น "SUSPECTED", เคส HPKP แนะนำ **ไม่ต้องแก้** |
| 🟡 รอได้ | OWASP ในเอกสารเป็นปี 2021 แต่ปัจจุบันคือ 2025 | ผูกทั้งสองปี |

## ช่องโหว่จากเอกสาร แยกตามหมวด (ภาพรวม)

| หมวด | ตัวอย่าง | ตรวจอัตโนมัติได้ไหม |
|---|---|---|
| ตั้งค่า/Header (CONF) | HSTS, CSP, Clickjacking, Cache, HTTP methods | ✅ ส่วนใหญ่ได้ |
| เข้ารหัส/TLS (CRYPT) | TLS 1.0/1.1, cipher อ่อน, ใบรับรอง | ✅ บางส่วน (cipher ต้องใช้เครื่องมือเฉพาะ) |
| Cookie/Token (SESS) | Secure, HttpOnly, SameSite, JWT | ✅ ได้ |
| ข้อมูลรั่ว (INFO/PRIV/ERR) | เวอร์ชัน server, stack trace, IP ภายใน, อีเมล, เลขบัตรประชาชน | ✅ ได้ (บางเคสต้องให้คนยืนยัน) |
| สิทธิ์/ยืนยันตัวตน (AC/AUTH) | Fake login, API ไม่มี auth, IDOR, CORS | ⚠️ CORS ได้แล้ว ที่เหลือรอบ M2 |
| Injection (INJ) | SQLi, Script, LDAP, XSS, LFI, Header manipulation (1,077 จุดจาก helper ตัวเดียว) | ❌ ต้องทดสอบแบบได้รับอนุญาต / ตรวจที่ source |
| Infra (INFRA) | ICMP, SSH, FTP, DB port, แพตช์ OS | ❌ นอกขอบเขต Web (ใช้เครื่องมือ VA) |

## หลักฐานการปรับปรุง (คัดมาเฉพาะที่สำคัญ)

1. **ทดสอบอัตโนมัติ 30 รายการ ผ่านทั้งหมด** (`npm test` → pass 30, fail 0) เช่น ห้ามยิงไปโดเมนอื่น, redirect หนีออกนอก scope ถูกบล็อก, host ที่ชี้ไป IP ภายในถูกบล็อก "ก่อนส่งแม้แต่ byte เดียว", รายงานไม่มีข้อมูลลับหลุด
2. **ด่านตรวจในเครื่องผ่านครบ 8/8** (`npm run gate`) ได้แก่ ไม่มี workflow, test ผ่าน, ไม่มีช่องโหว่ใน dependency (npm audit 0), lockfile ถูกต้อง, ไลเซนส์/ToS อนุมัติครบ, สร้าง SBOM ได้, ไม่มีข้อมูลลูกค้าหลุด
3. **Demo ก่อน/หลังแก้:** แอปตัวอย่างที่มีช่องโหว่พบ 34 findings หลังแก้เหลือ 5 (ทั้งหมดคือ "ยังเป็น HTTP" ซึ่งเป็นธรรมชาติของ demo ในเครื่อง) และ `compare` ได้ผล **IMPROVED_NO_DRIFT** คือแก้ได้ 14 เคสโดย **ไม่เปลี่ยน Response ของผู้ใช้จริงเลย** → [compare.md](../samples/compare.md)
4. **ตรวจซ้ำบนหน้าเว็บจริง (Browser):** เปิดแอปตัวอย่างใน Browser แล้วพบว่าเวอร์ชันที่แก้แล้ว Browser **ปฏิเสธการฝัง iframe จากเว็บอื่น** (console: `violates ... "frame-ancestors 'self'"`) และ JavaScript **อ่าน session cookie ไม่ได้** ส่วนเวอร์ชันมีช่องโหว่อ่านได้ ซึ่งตรงกับผลของ NavSentry → [ภาพหลักฐาน](evidence/browser-recheck-frame-ancestors.jpg)
