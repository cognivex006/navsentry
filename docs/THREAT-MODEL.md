# Threat Model

Assets: target availability and data; credentials for test actors; evidence/report contents; the operator's machine; the NavSentry supply chain; the owner's GitHub account.

| ID | Threat | Control (implemented) | Residual / planned |
|---|---|---|---|
| TM-01 | Scanning an unauthorized host (typo, redirect, link) | Origin allowlist, authorization acknowledgement, redirect re-check per hop, no crawling | Live discovery (M1b) must reuse the gate |
| TM-02 | DNS rebinding / SSRF into internal or cloud metadata | Connect-time `lookup` validation of every address; metadata always blocked; named private approvals | The playwright engine fulfils every request through direct-http, so the same connect-time check applies; the browser itself has no network path ([ADR-0008](adr/0008-playwright-engine-s1.md)) |
| TM-03 | Causing damage (state change, DoS) | Safe methods only in observe; `allow_mutations` refused; budgets; production observe-only; no payload code; safe-validate writes only to declared fixture entries (TM-32, TM-33) | See TM-32 and TM-33 |
| TM-04 | Leaking secrets/PII into reports | Redaction before persistence; set-cookie values dropped; binary withheld; tests scan artifacts | Redaction is defensive, not proof; unknown formats may pass |
| TM-05 | Prompt injection from target content | Target data never interpreted as instructions; agent skill states it; checks are deterministic code | LLM planner (future) must keep this boundary |
| TM-06 | Command injection via CLI transports | argv arrays, `shell:false`, fixed executable paths, scrubbed env, `-q` for curl, fixed PowerShell script | Execution not enabled until M3 tests on each OS |
| TM-07 | Malicious/compromised dependency | Zero runtime deps; exact pins; ignore-scripts; lockfile sha512 + registry check; audit; SBOM; terms register | Single advisory source; no signature verification of npm tarballs beyond integrity |
| TM-08 | Owner account suspension (platform policy) | No GitHub Actions/Apps/bulk API automation; public repo content reviewed against GitHub AUP | Owner should remove `workflow` token scope |
| TM-09 | Publishing customer data from source reports | SRC labels; GATE-08 with untracked owner terms; catalog anonymization test | Depends on the owner keeping the terms file current |
| TM-10 | False assurance ("zero findings = safe") | Coverage matrix with NOT_TESTED reasons; INCOMPLETE security result; wording in every report | Human review still required |
| TM-12 | A flow file widens scope (origin, path, method, headers) | No host keys; static ScopeGate lint; runtime ScopeGate per request and redirect hop; unknown keys rejected; no custom headers | — |
| TM-13 | Target-controlled values steer requests (extracted IDs) | Strict value charset, `.`/`..` rejected, whole-segment substitution with encoding, ScopeGate after substitution, no header templating; cross-flow values only through declared `imports` from PASS steps, never across actors or origins unless the reviewed flow says so | — |
| TM-14 | Prompt injection through analyzer inputs (run.json, story text, target repos) | Deterministic analyzer; narrative never executed or reported; generated flows are drafts; skill: data, not instructions | Host agent discipline |
| TM-15 | Secrets or PII committed in consumer flow files | Env references only; `fill` values only via vars; every literal scanned with the Redactor detectors; secret-like keys rejected | Unknown formats may pass the detectors |
| TM-16 | False assurance: "E2E passed" while UI steps did not run | Router-based executability; INCOMPLETE, never PASS; "HTTP-level only" label; manual replay kept separate | — |
| TM-17 | Load caused by many flows | Shared budget and rate limit; no loops or retries; step/flow limits; estimate in `plan` | — |
| TM-18 | Baking vulnerable or erroneous behaviour into expectations | Analyzer skips ≥500, security headers, cookies and values; "public?" decisions left to the owner; security checks independent of expectations | Owner may approve a wrong expectation |
| TM-19 | GET with side effects (logout, delete links) | Lint warning; analyzer skips such paths; skill requires owner confirmation | GET side effects are invisible to NavSentry |
| TM-20 | Self-approval by an agent | Hash-pinned approval; skill rule; drafts capped at SUSPECTED; drafts refused for production | Approval is a process control, not identity |
| TM-21 | Production run outside the authorized window, or with a live credential | Production profile requires `reference` and `expires_at`; window checked before any request; Budget re-checks the deadline after each wait and aborts in-flight requests; live-key prefixes refused unless `allow_live_tokens` | Clock skew between operator and owner |
| TM-22 | Silent truncation of large bodies hides evidence | Streamed capture records `complete \| truncated \| aborted`, byte counts and a hash; partial bodies make the run PARTIAL and body assertions INCONCLUSIVE | Detectors still inspect a bounded prefix until 0.1.3-s |
| TM-23 | Raw captures or helper scripts left in a consumer project | Locked `.navsentry/work/<run-id>/` deleted at exit and on signals; before/after snapshots → exit 4; GATE-09 for this repository | Metadata snapshots do not prove byte identity; SIGKILL leftovers are swept on the next run |
| TM-24 | Cleanup deleting the wrong files (tampered inventory, links, PID reuse) | Deletion only inside canonical work roots under one explicit project root; links and junctions unlinked, never followed; linked ancestors refused; lock with nonce, host and process start; uncertain ownership preserved | A live reused PID keeps a stale directory until the owner cleans it |
| TM-25 | Crawler widens scope or causes load (links, redirects, query variants) | Static ScopeGate before queueing plus the runtime gate; hop-by-hop redirect re-check and loop stop; template sampling with a 2N ceiling; frontier, page, depth and request limits; robots enforced in production; no forms or parameter changes | Sampled-out pages are not tested |
| TM-26 | Asset content or secrets reaching artifacts or the agent | Bodies spooled only in the work directory and deleted; no excerpts for assets; facts carry kind, position and length only; masked previews; cache holds facts, never values or verdicts; `client-findings.json` capped | A format match does not prove a key is live |
| TM-27 | Exposure probes treated as fuzzing or forced past scope | Fixed list, HEAD first, ScopeGate and Budget per request, out-of-scope probes NOT_TESTED, opt-out via `checks.disabled` | — |
| TM-28 | Advisory text or proposals steer actions, or leak target data | Snapshot and proposals are data: rendered escaped, never commands, PoCs or check activations; lookups and proposals make zero network requests; source URLs validated, never fetched; proposals reject secrets, addresses, personal data and target hosts; unrecognised banner names withheld | Promotion relies on maintainer review |
| TM-36 | Console output or page errors carry secrets into NavSentry artifacts | Messages are inspected in memory on arrival and never written; only case, source, masked preview and a value-free template hash are kept (S8); capture limits count dropped messages as incomplete | A message larger than the byte budget is not inspected (counted as dropped) |
| TM-37 | The visual driver is steered off scope by page text, or another local process drives the session | The browser is NavSentry's: every request still goes through ScopeGate and the Budget whatever is clicked (ADR-0009); commands need a 256-bit token over a local pipe only; every action is logged; idle, deadline, budget and action caps end the session | Screenshots reach the host agent's model provider (owner consent in the manifest); prompt injection can still waste clicks within scope |
| TM-32 | A safe-validate mutation hits real data | Development profile only; writes only to declared entries; `ScopeGate.checkMutation` on the normalised path with one id segment per placeholder; strict id rule before any URL is built; mutations never follow redirects; cleanup only by ids this run extracted ([ADR-0010](adr/0010-safe-validate-fixtures.md)) | A mis-declared fixture endpoint can touch real data; browser form bodies are checked only for content type and size |
| TM-33 | Test data is left behind | Fsynced pending intent before each create; Budget cleanup reserve; cleanup window before the earlier deadline; one retry; `verify_gone`; leftovers or a lost create make the run FAILED (exit 2) with the exact manual action; signal coordinator; the next sweep reports pending intents and deletes nothing | Side effects such as emails, webhooks and audit rows are not cleaned; SIGKILL leaves cleanup to the owner |
| TM-34 | Credentials leak through login | Env-only values; credentials and every session cookie value are known Redactor secrets (also for console facts); filled values never returned or logged; request bodies recorded as sha256 only; `cookie_env` refused in production; the visual driver never types | A target that echoes a credential in an unusual encoding may evade literal redaction |
| TM-40 | The recorder extension leaks data, is steered by a page, or a crafted .navrec.zip attacks the importer | The extension has no network APIs (CSP `connect-src 'none'`, checked statically), no up-front host access (one origin at a time from the imported manifest), and never reads field values or photographs password fields. URLs keep query keys, never values. On import, the archive is read through its central directory: name allowlist, no traversal, duplicates, symlinks or encryption, entry, count and expansion limits, CRC and per-file sha256. Out-of-scope steps are listed, never encoded. Notes stay in RECORDING.md as data. Screenshots go to a git-ignored folder. Tests: `test/navrec.test.ts`; the extension's runtime is not exercised (needs a headed browser with the extension loaded; not automated) |
| TM-39 | Typing in the visual driver leaks a secret or submits a form | Values come from an environment variable of the session (`--env`, added to the redactor as a known secret) or are short literal text. Literal text is refused in password fields and when the redactor would change it (a secret or personal data). The action log records the field, env name, length and a 12-character sha256 prefix of literal text, never the value. Typing never submits, and a POST submit is still refused because the visual driver stays observe-only. Draft flows from `--save-flow` turn every input into an env variable. `--headed` uses the full Chromium build (owner-approved with conditions 2026-11-13) with the same request routing; a person's clicks are logged as human and never go into draft flows. Tests: `test/visual-d.test.ts` |
| TM-38 | An agent uses the MCP server to widen scope, approve its own flows or answer authorization questions | `navsentry mcp` is stdio only (no listener). Tools run the CLI as a child process with an argument array (no shell), so every CLI refusal, ScopeGate and Budget applies. Argument values that start with `-`, contain newlines or are not strings are refused. There is no tool for `init`, `flow approve`, `workspace clean`, `doctor update` or manifest edits. Traffic-sending tools carry `openWorldHint` so the host can ask the user. Tests: `test/mcp.test.ts` |
| TM-35 | A CSRF probe is treated as an attack | Reserved `https://navsentry-csrf-probe.invalid` origin; only `allowed_mutations` entries the owner marked with `csrf`; cookie-session actors only; three requests per step, each a declared fixture mutation counted against `max_mutations` | — |
| TM-29 | Reading a target repository executes or follows untrusted content | Read-only walk: no code execution, links and junctions skipped, size, depth and entry caps, only validated route strings and package identities kept; OpenAPI text never copied into flows; workspace check proves no change (exit 4) | Route detection is pattern-based and may miss or misread declarations |
| TM-30 | Page content reaching the agent through analysis | Page models carry allowlisted structure only; values, text and secret-looking names withheld; display URLs; opt-in free text redacted and cut; 64 KiB cap; leak scan before promotion; models rejected on unknown fields | Pattern redaction cannot prove free text free of personal data (opt-in only) |
| TM-31 | Model-generated extractor code executed | Extractors are JSON data with a selector subset, attribute allowlist and fixed predicates (no regex); non-JSON files refused; drafts live only in the work directory | — |
| TM-11 | Over-trusting scanner output in sources | SUSPECTED lifecycle, checksum validation, caveats, HPKP dismissal | Owner-specific exceptions must be recorded per project |
